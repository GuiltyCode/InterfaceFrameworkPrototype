🔧 Discord OAuth2 — Backend Setup Guide

📋 Overview

Discord OAuth2 requires a backend server to safely exchange the auth code for a token without exposing your Client Secret to the browser. This guide walks through the full setup.

What we're building:

  • A Discord Application (Client ID + Secret)
  • Two new routes on the Node.js server: /auth/discord and /auth/discord/callback
  • Update Index.html with your Client ID

Flow:

  1. User clicks "Sign in with Discord" in the browser
  2. Browser redirects to Discord's auth page
  3. User approves → Discord redirects back to /auth/discord/callback with a code
  4. Server exchanges the code for a token (Client Secret never leaves the server)
  5. Server fetches user profile from Discord, creates a session, redirects to /
  6. Existing session check in Index.html picks up the session and logs the user in
Step 1 — Create a Discord Application
  1. Go to discord.com/developers/applications
  2. Click New Application and give it a name (e.g. SteelfangsDen)
  3. In the left sidebar click OAuth2
  4. Under Redirects, click Add Redirect and enter:
    http://localhost:3000/auth/discord/callback
    When you deploy to a real domain later, add that URL here too, e.g. https://yourdomain.com/auth/discord/callback
  5. Note down your Client ID (visible on the OAuth2 page)
  6. Click Reset Secret to generate your Client Secret — save this somewhere safe, you won't see it again
Step 2 — Install the discord-oauth2 package

In your terminal, navigate to the server folder and run:

cd server
npm install discord-oauth2
Step 3 — Add the routes to server/server.js

Open server/server.js and add the following. Place the constants near the top of the file (after your existing require statements) and the routes alongside your existing /api/login route.

server/server.js — add near top
const DiscordOAuth = require('discord-oauth2');
const oauth = new DiscordOAuth();

const DISCORD_CLIENT_ID     = process.env.DISCORD_CLIENT_ID     || 'YOUR_CLIENT_ID_HERE';
const DISCORD_CLIENT_SECRET = process.env.DISCORD_CLIENT_SECRET || 'YOUR_CLIENT_SECRET_HERE';
const DISCORD_REDIRECT      = process.env.DISCORD_REDIRECT      || 'http://localhost:3000/auth/discord/callback';
server/server.js — add routes
// GET /auth/discord
// Redirects the user to Discord's OAuth2 authorisation page.
app.get('/auth/discord', (req, res) => {
    const url = oauth.generateAuthUrl({
        scope:       ['identify', 'email'],
        clientId:    DISCORD_CLIENT_ID,
        redirectUri: DISCORD_REDIRECT
    });
    res.redirect(url);
});

// GET /auth/discord/callback
// Discord redirects here after the user approves.
app.get('/auth/discord/callback', async (req, res) => {
    const { code } = req.query;
    if (!code) return res.redirect('/?error=no_code');

    try {
        // Exchange code for access token
        const tokens = await oauth.tokenRequest({
            clientId:     DISCORD_CLIENT_ID,
            clientSecret: DISCORD_CLIENT_SECRET,
            redirectUri:  DISCORD_REDIRECT,
            code,
            scope:        ['identify', 'email'],
            grantType:    'authorization_code'
        });

        // Fetch user profile from Discord
        const user = await oauth.getUser(tokens.access_token);

        // Create session — same structure as email/password login
        req.session.user = {
            id:       'discord_' + user.id,
            username: user.username,
            email:    user.email || null
        };

        // Redirect back to the front page — session check in Index.html handles the rest
        res.redirect('/');
    } catch (err) {
        console.error('[discord oauth]', err);
        res.redirect('/?error=discord_failed');
    }
});
Security note: Never hardcode your Client Secret in a file you commit to GitHub. Use environment variables (process.env.DISCORD_CLIENT_SECRET) or a .env file that is listed in .gitignore.
Step 4 — Update Index.html with your Client ID

In Index.html, find this section in the <script> block:

var DISCORD_CLIENT_ID = 'YOUR_CLIENT_ID_HERE';
var DISCORD_REDIRECT   = window.location.origin + '/auth/discord/callback';

Replace YOUR_CLIENT_ID_HERE with your actual Discord Client ID:

var DISCORD_CLIENT_ID = '123456789012345678';
var DISCORD_REDIRECT   = window.location.origin + '/auth/discord/callback';
The Client ID is not a secret — it's safe to put in frontend code. Never put the Client Secret here.
Step 5 — Add a .env file for your secrets (recommended)

Create a file called .env inside the server folder:

server/.env
DISCORD_CLIENT_ID=123456789012345678
DISCORD_CLIENT_SECRET=your_secret_here
DISCORD_REDIRECT=http://localhost:3000/auth/discord/callback
SESSION_SECRET=change-this-to-a-random-string

Then install dotenv and load it at the very top of server.js:

npm install dotenv
server/server.js — first line
require('dotenv').config();

Add .env to your .gitignore so it never gets committed:

.gitignore
server/.env
server/node_modules/
Step 6 — Serve Index.html from the Express server

For the Discord redirect to work, the browser and the API need to be on the same origin. The easiest way is to have Express serve your static files:

server/server.js — add after your middleware setup
const path = require('path');

// Serve the www folder as static files
app.use(express.static(path.join(__dirname, '..')));

// Fallback — serve Index.html for any unmatched route
app.get('*', (req, res) => {
    res.sendFile(path.join(__dirname, '..', 'Index.html'));
});

Then visit http://localhost:3000 instead of opening Index.html directly as a file.

The app.get('*') fallback must go after all your API routes, otherwise it will intercept them.
✅ Testing the flow
  1. Start the server: cd server && node server.js
  2. Open http://localhost:3000
  3. Click Sign in with Discord
  4. Approve on Discord's page
  5. You should be redirected back and logged in automatically

If something goes wrong, check the server terminal for the [discord oauth] error log.

📝 Notes for later
  • When you deploy to a live domain, add the production callback URL to your Discord app's Redirect list and update the DISCORD_REDIRECT environment variable.
  • Discord usernames no longer have discriminators (no #1234) — the user.username field returns the new unique username format.
  • Not all Discord users have a verified email — user.email may be null. The current code handles this gracefully.
  • To store Discord users in the MySQL database later, check for an existing row by discord_id and upsert rather than using email as the unique key.
