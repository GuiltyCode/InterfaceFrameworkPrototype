🔧 Login System — Backend Setup Guide

📋 Overview

The login and registration system uses a Node.js + Express backend with a MySQL database. Passwords are stored as bcrypt hashes — never plain text.

Architecture:

  • index.html — Login / Register page (calls /api/auth/login and /api/auth/register)
  • desktop.html — Main desktop (checks /api/auth/session on load, redirects to login if not authenticated)
  • server/server.js — Express app serving static files + API routes
  • server/routes/auth.js — Auth endpoints
  • server/routes/character.js — Character data endpoints
  • server/db.js — MySQL connection pools

API endpoints:

MethodEndpointDescription
POST/api/auth/registerCreate new account
POST/api/auth/loginLog in
POST/api/auth/logoutLog out (destroys session)
GET/api/auth/sessionGet current logged-in user
GET/api/characterGet character data for current user
POST/api/characterCreate or update character
POST/api/character/equipSet or clear active mobile suit
👥 User Roles

Every user account has a role stored in the users.role column. Three roles are available:

RoleDescription
UserDefault role. All registered accounts start here.
ModModerator. For future GM/moderation features.
AdminFull administrative access. Only the seed account starts here.

The role is returned by GET /api/auth/session and included in the login response, so the frontend can use it to show/hide admin features in future.

To change a user's role manually in MySQL:

USE steelfangsden_users;
UPDATE users SET role = 'Mod' WHERE email = 'someone@example.com';
Step 1 — Prerequisites

Make sure you have the following installed:

  • Node.js (v18 or later) — nodejs.org
  • MySQL (v8 or later) — via XAMPP, WAMP, MySQL Installer, or standalone

Verify both are available by running:

node --version
mysql --version
Step 2 — Create the databases

Run the setup SQL file against your MySQL server. This creates two databases and all required tables:

mysql -u root -p < server/setup.sql

Or open MySQL Workbench / phpMyAdmin and paste the contents of server/setup.sql directly.

Databases created:

  • steelfangsden_users — user accounts (users table) and character index (characters table)
  • steelfangsden_chars — full character data (character_data table) and inventory (inventory table)
If you get an access denied error, your MySQL root user may require a password or a specific host. Try: mysql -u root -p -h 127.0.0.1 < server/setup.sql
Step 2b — Create the default Admin account

After the SQL setup, run the seed script to create the default Admin account:

cd server
node seed.js

This creates the following account in steelfangsden_users:

FieldValue
UsernameAdmin
Emailadmin@steelfangsden.local
Passwordtest123
RoleAdmin
Change the admin password after first login. test123 is intentionally weak and for setup only. Update it in the database or add a password-change endpoint.

The script is safe to run multiple times — it checks if the admin already exists before inserting.

To update the password manually in MySQL:

-- Run from your terminal after npm install:
node -e "require('bcrypt').hash('your_new_password', 12).then(h => console.log(h))"

-- Then in MySQL:
USE steelfangsden_users;
UPDATE users SET password = 'PASTE_HASH_HERE' WHERE email = 'admin@steelfangsden.local';
Step 3 — Configure environment variables

Copy the example env file and fill in your values:

copy server\.env.example server\.env

Then open server/.env and edit it:

server/.env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_mysql_password_here

SESSION_SECRET=pick-a-long-random-string-here

# Discord OAuth2 — leave blank until configured
DISCORD_CLIENT_ID=
DISCORD_CLIENT_SECRET=
DISCORD_REDIRECT=http://localhost:3000/auth/discord/callback
Never commit .env to git. It contains your database password and session secret. It is already listed in .gitignore.
The SESSION_SECRET can be any long random string. Use a password manager to generate one, e.g. x7Kq2#mPzL9@vRnW
Step 4 — Install server dependencies

Navigate to the server folder and install packages:

cd server
npm install

This installs:

PackagePurpose
expressWeb framework / API server
express-sessionCookie-based session management
mysql2MySQL driver with Promise support
bcryptPassword hashing
corsCross-origin request handling
dotenvLoads .env file into process.env
Step 5 — Start the server

From the server folder:

node server.js

You should see:

SteelfangsDen server running on http://localhost:3000
  Login page : http://localhost:3000/index.html
  Desktop    : http://localhost:3000/desktop.html
Always access the site via http://localhost:3000 — do NOT open the HTML files directly as file://. Cookies do not work with file:// URLs and login will fail.
✅ Testing the login flow
  1. Open http://localhost:3000
  2. Click Create account and register a new user
  3. You should be redirected to desktop.html automatically
  4. Open a new tab and go to http://localhost:3000 — you should be redirected to the desktop (session persists)
  5. Click Log out from the System Menu — you should return to the login page

If anything fails, check the server terminal for error output.

Common issues:

  • ER_ACCESS_DENIED — wrong DB_USER / DB_PASSWORD in .env
  • ECONNREFUSED — MySQL is not running. Start it via XAMPP/Services
  • ER_NO_SUCH_TABLE — database setup SQL was not run. Repeat Step 2
  • Login fails silently — you're opening the file as file:// not http://localhost:3000
🔷 Discord OAuth2 Login (optional)

The Discord login button is present in the UI but inactive until configured. See setup/discordsetup.html for the full setup guide.

Short version:

  1. Create an app at discord.com/developers/applications
  2. Add http://localhost:3000/auth/discord/callback as a redirect URI
  3. Copy the Client ID and Secret into server/.env
  4. Set DISCORD_CLIENT_ID in index.html as well
📁 Server file structure
server/
  .env               ← your credentials (never commit this)
  .env.example       ← template — commit this
  package.json       ← dependencies
  server.js          ← Express app entry point
  db.js              ← MySQL connection pools
  setup.sql          ← run once to create databases + tables
  seed.js            ← run once to create default Admin account
  routes/
    auth.js          ← /api/auth/* endpoints
    character.js     ← /api/character/* endpoints
